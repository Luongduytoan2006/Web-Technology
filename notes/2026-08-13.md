# Công nghệ Web - 13-8-2026
## Buổi 1: Khái niệm về web, ôn lại 1 số kiến thức mạng.

## Khái niệm ban đầu về Web

- Web là một dịch vụ ra đời sau Internet.
- Internet là nền tảng mạng kết nối các máy tính; Web chạy trên Internet.

## Các thành phần cơ bản

- **Client**: phía người dùng, ví dụ máy tính hoặc điện thoại. (máy tính/điện thoại)
- **Web Client**: chương trình/phần mềm chạy trên máy Client. Ví dụ: trình duyệt như Chrome, Edge, Firefox. (có 2 việc, gửi yêu cầu và show ra giao diện)
- **Server**: phía xử lý yêu cầu, quản lý chương trình và dữ liệu. (máy chủ)
- **Web Server**: phần mềm/hệ thống trên server dùng để nhận request và trả response. (có 2 việc, đợi chờ để nhận yêu cầu, xử lý request, tìm trong tài nguyên, và trả response)

Ví dụ: khi sinh viên mở trang xem điểm bằng Chrome, máy tính là **Client**, còn Chrome là **Web Client**.

## Request và Response

- **Request**: yêu cầu do Client/Web Client gửi lên server.
- **Response**: kết quả server trả về cho Client/Web Client.

Ví dụ xem điểm:

1. Sinh viên bấm xem điểm trên trình duyệt.
2. Web Client gửi request lên server.
3. Server xử lý yêu cầu và lấy điểm từ database.
4. Server trả response về.
5. Web Client nhận thông tin và show ra giao diện thích hợp.

Nói ngắn gọn: muốn xem điểm bản thân thì phải gửi yêu cầu lên server; server trả thông tin về, Web Client nhận rồi hiển thị ra giao diện.

## Dữ liệu và giao diện

- Data không nằm trực tiếp trên giao diện, giao diện chỉ dùng để hiển thị và thao tác.
- Dữ liệu thật thường lưu trong database bên server.
- Khi cần hiển thị, server lấy dữ liệu từ database rồi trả về cho Web Client.

Ví dụ: điểm sinh viên không nằm sẵn trên trang web, mà được lấy từ database bên server rồi mới hiện lên giao diện.

## Địa chỉ IP, mạng máy tính

1 địa chỉ IP có 32 bit được chia là 4 nhóm, 2 phần, 2 loại.
2 phần bao gồm Net ID và Host ID, 2 loại là tĩnh và động.

- Net ID do **NIC** (1 tổ chức quốc tế chứ ko phải card mạng NIC) cấp. Nó dùng để xác định mạng.
- Host ID do trung tâm quản lý mạng cấp. Nó dùng để xác định máy trong mạng.
Net ID luôn bị che và mình cần tìm ra nó, vì nó là key để tra ra gateway.
Mặt nạ mạng nó sẽ che phần Net ID (vì do trung tâm NIC nó cấp).

VD: IP: 172.10.15.24 và subnet mask: 255.255.0.0
NET = IP AND Subnet mask = 172.10.0.0

Nếu bạn A gia nhập mạng với IP 172.16.1.5 và sửa điểm rồi tắt máy đi uống cafe. Sau đó bạn B gia nhập mạng với IP 172.16.1.5, sau đó bạn A vào lại và được cập IP mới là 172.16.1.15 thì để biết là A vẫn là người sửa điểm -> địa chỉ MAC sẽ được đính kèm theo IP và server sẽ biết là A vẫn là người sửa điểm.

Địa chỉ MAC gắn trên card mạng. Khi máy khởi động -> NIC gắn MAC vào -> máy khởi động lần sau -> NIC gắn MAC vào -> nếu MAC ko đổi thì server biết là A vẫn là người sửa điểm.

=> Nói là liên kết bằng địa chỉ IP nhưng thật ra các máy liên kết bằng địa chỉ vật lý (MAC)
**Địa chỉ MAC có 48 bit**, 24 bit cho mã nhà sản xuất, 24 bit phía sau dùng là mã thiết bị. 

Từ địa chỉ IP -> vật lý (ARP)
Từ vật lý -> IP (RARP)

Lập trình không có kết nối (URP): nó không cần kiểm tra kết nối, nó chỉ mong muốn truyền nhanh thôi. Nên là nó sẽ không phân giải miền. Ví dụ như DNS là 1 ví dụ điển hình.
Lập trình có kết nối (TCP): nó cần kiểm tra kết nối, nó cần phân giải miền. Ví dụ như HTTP là 1 ví dụ điển hình.

Tiêu chuẩn quốc tế ISO đã đưa ra mô hình mạng OSI: 
- Lớp 7: Application Layer (Ứng dụng)
- Lớp 6: Presentation Layer (Trình bày)
    - Đây là tầng trình diễn, đây là tầng mọi data sẽ được giải mã và hiển thị ra giao diện cho tầng 7.
- Lớp 5: Session Layer (Phiên)
    - Chỉ áp dụng cho lập trình có kết nối
    - Session nó lưu toàn bộ vết giữa Client và Server
- Lớp 4: Transport Layer (Vận chuyển)
    - TCP: có kết nối (mạng quét ra số 6)
    - UDP: không kết nối (mạng quét ra số 17)
- Lớp 3: Network Layer (Mạng)
    - Địa chỉ IP, giao thức IP, cấu trúc gói tin IP, phân chia mạng
    - Và có 1 cái mạnh để làm điều trên là Định tuyến Router mạng
- Lớp 2: Data Link Layer (Liên kết dữ liệu)
    - Tầng data link rất mạnh. Đây là nơi xảy ra ARP phân giải miền (từ IP -> MAC) và của RARP (vật lý -> IP)
    - Chức năng tầng data link là thế nào truyền bất đồng bộ, truyền đồng bộ, truyền có kiểm soát hay không có kiểm soát, và đặc biệt là bảo vệ an toàn cho gói tin.
    - Phương pháp bảo toàn CRC
- Lớp 1: Physical Layer (Vật lý)
    - Tầng vật lý là tầng giao thức mạng vật lý


Tầng mạng TCP/IP (4 tầng):
```
OSI                                      TCP/IP
7 6 5                                  -> 4. Ứng dụng
4                                      -> 3. Giao vận
3                                      -> 2. Internet
2 1                                    -> 1. Tiếp cận mạng
```

Lập trình viên (3 tầng):
- Presentation (giao diện)
- Module (xử lý)
- Data Management (lưu trữ)
 Đó chính là view <-> controller <-> model.


## 4 loại mô hình kiến trúc code (Phân bổ 3 tầng)

4 loại mô hình code
- Mô hình trình bày từ xa (Client chỉ hiển thị)
- Mô hình phân tán (Client - Server) - Model trình bày + client - Server (xử lý)
- Mô hình mượn tài nguyên phần cứng (Server chỉ lưu trữ data)
- Mô hình dữ liệu phân tán ở nhiều nơi

Dựa trên cách phân chia 3 tầng (Presentation - Module - Data Management) giữa Client và Server:

1. **Mô hình trình bày từ xa (Remote Presentation):**
    - **Client:** Chỉ làm nhiệm vụ **Hiển thị (Presentation)** giao diện.
    - **Server:** Đảm nhận toàn bộ **Xử lý (Module)** và **Lưu trữ (Data Management)**.
    - *Đặc điểm:* Client mỏng (Thin Client), dễ bảo mật nhưng Server dễ bị quá tải. Ví dụ: Web 1.0, Terminal, Remote Desktop.

2. **Mô hình phân tán (Client - Server / Distributed Application):**
    - **Client:** Hiển thị (Presentation) + một phần Xử lý nhẹ (Validate form, hiệu ứng).
    - **Server:** Xử lý nghiệp vụ chính (Module) + Lưu trữ (Data Management).
    - *Đặc điểm:* Giao tiếp qua API/JSON, giảm tải cho Server, trải nghiệm mượt mà. Ví dụ: Web SPA (React/Vue + API Backend), Mobile App.

3. **Mô hình mượn tài nguyên phần cứng (Remote Data Management):**
    - **Client:** Hiển thị (Presentation) + toàn bộ Xử lý nghiệp vụ (Module).
    - **Server:** Chỉ đóng vai trò kho lưu trữ dữ liệu thuần túy (**Data Management**).
    - *Đặc điểm:* Client "béo" (Fat Client) kéo data thô về tự xử lý, gây nặng mạng, Server đơn giản. Ví dụ: Phần mềm WinForms/C++ kết nối trực tiếp CSDL qua mạng LAN.

4. **Mô hình dữ liệu phân tán ở nhiều nơi (Distributed Data Management):**
    - **Dữ liệu (Data Management):** Được chia nhỏ hoặc sao chép rải rác trên nhiều máy chủ/Node ở các vị trí khác nhau.
    - **Presentation & Module:** Nằm ở Client/Server, còn tầng Data được phân tán.
    - *Đặc điểm:* Mở rộng và chịu lỗi cực tốt (High Availability), nhưng đồng bộ dữ liệu phức tạp. Ví dụ: CSDL phân tán (MongoDB Cluster, Cassandra), hệ thống chi nhánh ngân hàng.
